# MCP OAuth (H6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/mcp` accepts OAuth access tokens (JWTs) from an external OIDC identity provider, so MCP clients that require OAuth (claude.ai / desktop custom connectors) can connect, with the same identity and rights as the mapped Arneb user.

**Architecture:** Arneb is an OAuth 2.1 *resource server* only (spec non-goal: no authorization server). A new `[oauth]` section names the issuer and the public `/mcp` URL. The Web auth middleware sends JWT-shaped bearers on `/mcp` to an `OAuthValidator` (JWKS discovered from the issuer, cached, refreshed on unknown `kid`), maps a configured claim to an existing state-store user, and sets `Identity { via: AuthVia::OAuth }`. `/.well-known/oauth-protected-resource` (RFC 9728) and a `resource_metadata` parameter on `/mcp`'s `401` let clients discover the provider, per the MCP authorization spec.

**Tech Stack:** Rust, axum 0.8, `jsonwebtoken` 10 (aws-lc-rs backend, already the process's crypto stack), `reqwest` 0.13 (already in the tree via object_store), `url`, Keycloak (dev mode, Tier 2 only).

**Spec:** `docs/superpowers/specs/2026-10-30-headless-agent-interface-design.md` (Credentials and identity → OAuth; Stages → H6; Acceptance → OAuth). Base branch: `feat/runtime-config` (PR #219).

## Decisions (my calls, for the user to check)

- **D1 — `/mcp` only.** JWTs are accepted on `/mcp` and nowhere else; on `/api/*` and `/metrics` a JWT is just an invalid bearer (`401`). The spec scopes H6 to MCP. *Cost if wrong:* widening is one condition in `authenticate` plus tests.
- **D2 — the mapped user must already exist** in the state store (config seed or `create_user`). No auto-provisioning. A valid token for an unknown user → `403 forbidden` (not `401`, which would loop the client's OAuth flow). Deleting the user (H5) revokes OAuth access on the next request. *Cost:* an admin creates each OAuth user once.
- **D3 — default `user_claim = "sub"`.** `sub` is the only claim OIDC guarantees stable and unique; `preferred_username` / `email` are mutable in some IdPs and are opt-in (documented with that warning). *Cost:* with the default, Arneb user names are IdP subject ids.
- **D4 — audience defaults to the resource URL** (RFC 8707 / MCP spec "tokens must be issued for this resource"); `aud` must contain it. Configurable for IdPs that can only emit a client id.
- **D5 — asymmetric algorithms only:** RS256, RS384, RS512, PS256, ES256, ES384. `none` and HS* are always refused (no algorithm confusion). Not configurable.
- **D6 — IdP unreachable → `503 auth_provider_unavailable`** (`Retry-After: 5`), not `401`, when no cached key can decide. API tokens, sessions and Basic on `/mcp` keep working regardless.
- **D7 — an OAuth identity has the same rights as the user**, including `create_token` (minting an API token). Revoking the user at the IdP does not revoke Arneb API tokens already minted; documented. *Cost if wrong:* refusing `create_token` for `via = oauth` is one check.
- **D8 — `[oauth]` is startup-only** config (like ports and TLS), not state-store data; changing it needs a restart. Requires `[auth] type = "password"` and `[mcp] enabled`; otherwise startup fails with a named error.
- **D9 — plain-`http` issuer / resource only for loopback hosts** (local testing); anything else must be `https`.

## Global Constraints

- Every runtime knob has an `ARNEB_*` env override and its effective value is logged on target `arneb::config` at startup (CLAUDE.md).
- `thiserror` for library error types, `anyhow` only in the binary's config/main; `tracing`, never `log`. Public items get doc comments.
- No second crypto stack and no second copy of an existing crate: `cargo tree -d -p arneb-server` must show no new duplicate of `reqwest`, `rustls`, `aws-lc-rs`, `ring`; `jsonwebtoken` uses its aws-lc-rs backend.
- Never log or audit a token, a JWT, or a password. A rejected token is logged at most as its reason code (`expired`, `bad_audience`, …) on target `arneb::oauth` at DEBUG.
- All `401`s keep one identical body (`unauthenticated` envelope) — the existing `unknown_token_id_and_wrong_secret_are_indistinguishable` test must keep passing; under `[oauth]` only the `WWW-Authenticate` header on `/mcp` changes.
- Clippy on Rust 1.99.0 with `--workspace --all-targets -D warnings`, `cargo fmt -- --check`.
- With no `[oauth]` section, behavior is byte-identical to today (headers included).
- Do not stop, restart or reconfigure the user's running Docker containers; Tier 2 may start only the new `keycloak` service.

## Review Focus

1. **IdP down at startup or later** → the server starts (WARN once), OAuth requests get `503 auth_provider_unavailable`, cached keys keep validating until `jwks_cache_secs`, API tokens on `/mcp` unaffected. Test: `idp_down_is_503_and_api_tokens_still_work` (Task 2/4).
2. **Key rotation and unknown-`kid` floods** → a token with a new `kid` triggers one JWKS refetch and is accepted; 100 tokens with random `kid`s cause at most one fetch per `jwks_min_refresh_secs`. Test: `rotation_refetches_once_and_floods_are_rate_limited` (Task 2).
3. **Tokens that must not pass:** wrong `aud`, wrong `iss`, expired beyond leeway, `nbf` in the future, `alg: none`, HS256 signed with the public key bytes, a valid signature from a key not in the JWKS, a 20 KiB token. Test: `rejects_every_bad_token_class` (Task 2).
4. **Runtime user deletion (H5)** → the next request with a still-valid token is `403`. Test: `deleted_user_is_refused_on_the_next_request` (Task 4).
5. **Resource URL shapes:** trailing slash, explicit port, a proxy prefix (`https://h/arneb/mcp`) → metadata `resource` equals the configured string exactly and `resource_metadata` is `origin + /.well-known/oauth-protected-resource + path`. Test: `metadata_url_for_resource_shapes` (Task 3).

### Task 2: `OAuthValidator` (JWKS + JWT validation)

**Files:**

**Interfaces:**
- Consumes: `OAuthConfig` (Task 1).
- Produces:

  - `pub struct OAuthPrincipal { pub user: String, pub scopes: Vec<String> }` — `user` is the string value of `user_claim`; scopes from `scope` (space-separated string) or `scp` (string array).
  - `#[derive(Debug, thiserror::Error)] pub enum OAuthReject { Invalid(&'static str) /* reason code */, InsufficientScope, Unavailable }`.
  - `pub fn looks_like_jwt(token: &str) -> bool` — three non-empty dot-separated segments and not starting with `arneb_`.
- Behavior to pin:
  - Keys: `jwks_uri` if configured, else `{issuer without trailing /}/.well-known/openid-configuration` → its `jwks_uri`; the discovered document's `issuer` must equal the configured issuer exactly (else `Unavailable` + WARN naming both). HTTP timeout 5 s (a `const`), response bodies capped at 1 MiB.
  - Cache: keys by `kid`; refreshed when older than `jwks_cache`; an unknown `kid` (or a token without `kid` when the set has more than one key) triggers a refresh at most once per `jwks_min_refresh`, single-flight (concurrent callers await the same fetch). A failed refresh keeps the old keys until `jwks_cache` elapses.
  - Validation: token length ≤ 16 KiB (else `Invalid("too_large")`); header `alg` in D5's list and matching the JWK's `alg`/key type; `iss` == issuer; `aud` contains the audience; `exp` required; `nbf` honored; leeway applied; `user_claim` present and a non-empty string (else `Invalid("no_user_claim")`); every `required_scopes` entry present (else `InsufficientScope`).
  - `Unavailable` only when no key could decide because fetching failed; a token whose `kid` is unknown after a successful refresh is `Invalid("unknown_key")`.
