## 1. SCRAM-SHA-256 core (`crates/protocol/src/auth.rs`)

- [x] 1.1 `ScramVerifier`: derive the verifier from a password (SASLprep + PBKDF2-HMAC-SHA256), parse and print the PostgreSQL `SCRAM-SHA-256$iter:salt$StoredKey:ServerKey` format, and redact keys in `Debug`
- [x] 1.2 Constant-time client-proof check and server signature
- [x] 1.3 `UserCredentials`: reject an empty list, empty names and duplicates, and derive decoy verifiers for unknown users from a per-process secret
- [x] 1.4 `AuthMethod { None, ScramSha256 }`, with `None` as the default
- [x] 1.5 Unit tests: RFC 7677 test vector (client proof and server signature), verifier text round-trip, right and wrong password, malformed verifiers, credential validation, stable decoy salt, client-first parsing, errors forced to FATAL

## 2. Startup handler

- [x] 2.1 `AuthStartupHandler` state machine: Startup → AuthenticationSASL → SASLInitialResponse → SASLContinue → SASLResponse → SASLFinal → `finish_authentication`
- [x] 2.2 Return `FATAL 28P01` for a wrong password or unknown user, and `FATAL 08P01` for protocol violations (channel binding, authzid, nonce mismatch, unexpected message)
- [x] 2.3 Promote every authentication-phase error to FATAL (`ensure_fatal`) so pgwire never moves an unauthenticated connection to `ReadyForQuery`
- [x] 2.4 `none` mode keeps the previous trust-mode behavior exactly
