## Context

The roadmap's G6 asks for a concurrency soak in CI and smoke tests from
Superset, Metabase and dbt. The soak script exists
(`benchmarks/tpch/scripts/concurrency_soak.sh`) but needs a cluster; the kind
job (#182) builds an image and a cluster, but takes 13 minutes. Clients had
only been exercised through the protocol test suites, which replay
hand-written requests.

## Decisions

### D1 — A native cluster in CI, reusing the release build

The CI release build already compiles the binary; it now uploads it, and a
job starts a coordinator and two workers from it on TPC-H SF1 Parquet
generated by DuckDB (`gen_tpch.py` from #182). No image build, no kind:
the job is bounded by data generation and pip installs.

### D2 — Real client libraries, not their applications

Superset is checked through SQLAlchemy's Trino dialect (the same calls its
"add database" and table preview make: inspector + a reflected query), dbt
through dbt-trino, both pinned. Starting Superset or Metabase in CI would
mean a database, an admin bootstrap and minutes of startup for little more
coverage than the driver layer, which is where every failure found here
was. Metabase is not covered; the docs say so.

### D3 — Read-only dbt

Arneb cannot materialize models (no writable connector in the smoke
cluster), so the project uses source tests, an ephemeral model, `dbt show`
and `dbt docs generate`. `docs generate` exercises the heaviest metadata
query dbt sends.

### D4 — Fix what the clients hit, at the layer that owns it

- Case folding is done on lookup failure in `CatalogManager`
  (`fold_reference_case`), not in the parser: the parser keeps no quoting,
  and a name that matches as written must keep working (PostgreSQL
  connector tables with mixed case).
- `[catalog.]schema.table.column` keeps the last two parts: qualifiers
  match a table by name or alias, so dropping the schema is exact unless two
  tables with the same name from different schemas are joined without
  aliases.
- `JOIN … USING` becomes an equality `ON`, and the right copy of each
  column is hidden from unqualified references and `*`. The merged column
  takes the left value, which is correct only for inner and left joins;
  `RIGHT` / `FULL` are refused rather than returning wrong values.
- Bind parameters stay textual substitution, but each value is rendered as
  a literal of its declared type; binary values of types Arneb does not
  decode are refused, never turned into NULL.

### D5 — pg_catalog is its own change

Over pgwire, catalog introspection is string matching in `metadata.rs`,
returning whole rows regardless of the projection. SQLAlchemy's
`postgresql` dialect, dbt-postgres and Metabase's PostgreSQL driver all
join `pg_catalog` tables and cast to `regclass`; fixing that means real
virtual `pg_catalog` tables and new types. That is the next change; this
one covers the Trino path end to end and the pgwire driver basics.

## Risks / Trade-offs

- **Case folding is lenient.** `FROM "NATION"` (quoted, upper case) finds
  `nation`, which PostgreSQL would refuse. Arneb cannot tell quoted from
  unquoted names after parsing.
- **The soak at SF1 is light** (a round takes seconds). It catches failures
  under concurrency, not capacity limits; SF10 soaks stay a Tier 2 manual
  run.
